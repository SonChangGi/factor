# Factor 운영

공개 주소는 `/factor/`, Python 패키지는 `factor_lab`, 명령은 `factor`입니다. 이전 `/momentum-factor-lab/`는 새 주소 안내와 기존 immutable 데이터 경로만 제공합니다. Best 전용 저장소·예약·실행 경로·자료는 2026-10-21 최종 삭제했습니다. 이관한 팩터 정의와 95종목은 Factor의 공통 입력으로 유지합니다. [최종 정리 기록](best-retirement-2026-10-21.md)

## 정기 실행

- Daily Factor Dashboard: UTC 월~금 22:17, 한국 화~토 07:17. 미국 거래일 마감 후 실행합니다.
- Watchdog: 한국 화~토 10:47·14:17. NYSE 완료 거래일과 저장 결과·공개 파일을 확인합니다.
- 미국 휴장일·서머타임·조기 폐장은 거래소 달력으로 판정합니다. GitHub 대기로 실제 실행은 늦어질 수 있습니다.
- Factor·SOX·ETF가 먼저 시작한 수집을 확인해 중복 부하를 줄입니다. 각 수치 라이브러리는 한 코어로 제한합니다.

Daily 계산·입력 진단은 `ubuntu-24.04`에서 실행하며 `ubuntu-latest`의 운영체제 자동 전환을 따르지 않습니다.

Daily는 정확한 소스 SHA를 고정하고 `uv 0.11.17`과 `uv.lock`으로 환경을 설치합니다. 무료 가격·거래량을 수집해 불변 입력 스냅샷을 만들고, 승인된 기업행사·식별자 수정 정책을 적용합니다. 충돌이나 새 기업행사가 기존 수정의 가격 기준을 바꾸면 검토를 위해 중단합니다.

26개 고정 팩터와 월별 순차 선택, 동일 버전의 7개 스트레스, 2,000회 블록 재표집을 계산합니다. 입력·회계·756일 후보·월별 보유·지표·소스·실제 의존성 버전을 검증하고, 이전 정상 결과와 겹치는 역사도 대조합니다. 과거 NAV의 상대 변화가 10bp를 넘거나 유효 관측/결측 상태·과거 선택이 달라지면 자동 공개하지 않습니다.

검증된 후보는 입력 캐시 존재 확인과 원격 기준 SHA 재확인을 거쳐 교체합니다. 결과 커밋의 정확한 SHA로 Pages를 요청하고 공개 파일을 바이트 단위로 대조합니다. 수집·검증·캐시·경합·공개 대조 실패 시 실패로 기록하고 기존 정상 결과를 보존합니다. 모든 위험 기준을 탈락한 정상 데이터는 현금 선택이고, 데이터 오류와 구분합니다.

## 입력 보존

원가격과 시장 스냅샷은 공개 Pages에 포함하지 않고 해당 실행의 GitHub Actions cache 키로 보존합니다. 기본 무료 한도 10GB 안에서 사용하며 유료 저장 한도를 늘리지 않습니다. 7일 미사용과 용량에 따른 eviction이 적용되므로 영구 보관소가 아닙니다. 공개 manifest는 스냅샷 내용 해시와 캐시 키를 연결합니다. 실행 로그·검증 보고서는 별도 보존하며 캐시 유실 후 동일 원자료를 복구했다고 주장하지 않습니다.

기존 수동 결과는 당시 소스와 추출 소스 commit을 유지합니다. 이름 변경만으로 이전 결과의 codeHash나 입력 해시를 바꾸지 않습니다. 새 자동 결과는 `integrated-publication/v2` 계약과 실행 당시 런타임을 사용합니다.

## 재시도

기존 실행·입력·정상 결과·원격 main을 확인한 뒤 재시도합니다. Watchdog은 최신 결과가 있으면 재계산하지 않고 필요한 공개 파일 복구만 요청합니다. 수동 Daily는 명시적 요청이며 실패한 후보를 정상 결과에 덮어쓰지 않습니다.

부분적으로 잘린 가격 이력도 종목별 과거 관측수·시작일로 감지해 두 번 재시도합니다. 같은 완료 거래일의 실패 입력을 재사용할 때는 정확한 `reuse_input_cache_key`를 지정합니다. 원래 다운로드를 복사한 새 작업 공간에서 검사하며 기존 스냅샷을 수정하지 않습니다. `diagnostics_only`는 수집·계산·배포 없이 소형 진단 자료만 추출합니다.

매번 마지막 정상 입력의 캐시도 복원합니다. 공급자가 과거를 잃었으면 해시로 검증한 이전 종목 열 전체를 마지막 관측일까지 보존하고, 그 이후의 미확인 가격·거래량은 결측으로 둡니다. 서로 다른 조정 기준의 새 행을 임의로 붙이지 않습니다. 보유 종목의 새 평가가격이 없으면 기존 NAV 검증이 배포를 막습니다. 최초 빈티지 복원만 `archived_input_cache_key`를 명시하며 이후에는 정상 결과의 입력 캐시로 연결됩니다.

## 정의 정밀도 이전

CONSISTENCY·SIGNED_VP63 1.1은 같은 분할 기준의 종가·배당과 공급자 표현 정밀도로 수익 부호를 판정합니다. 원자료 구간이 0을 포함하면 보합이며, 임의 수익률 임계값을 사용하지 않습니다. 외부 가격 보정은 별도의 출처 정밀도를 선언합니다. MAX1M 1.1은 `(현재 종가 − 이전 종가 + 현금배당) / 이전 종가`의 월중 최대값을 사용합니다. 순위·비중 정책과 NAV 가격 입력은 그대로 유지합니다.

이 세 정의 변경은 자동 일일 갱신으로 승인하지 않습니다. `factor_lab.integrated_review`에서 기존 결과 ID·새 입력 해시·소스 SHA·실제 보존 캐시 ID를 고정하고 명시한 세 정의와 그에 의존한 월별 선택만 변경을 허용합니다. 다른 23개 팩터는 기존 10bp·결측 상태 검사를 그대로 통과해야 합니다. 독립 결과 검증을 마친 후보와 이전 비교를 `reviewed_definition_migration`으로 게시한 뒤 이후 일일 실행은 다시 일반 검증을 사용합니다. [실제 원자료 대조](source-return-audit-2026-10-20.md)

상장시장·공급자 티커 변경은 `integrated_listing_transitions.json`의 시행일·근거·별도 버전으로 관리하며 합집합 종목 ID는 바꾸지 않습니다. 2026-10-19부터 UUU의 공급자 조회는 DCM, CECO·IBOC의 시장 표시는 TXSE를 사용합니다. 원응답 티커를 보존하고 계산 열만 기존 ID로 정규화하며, 별칭이 바뀐 캐시는 재사용하지 않습니다. 새 티커의 전체 이력이 불완전하면 기존 빈티지의 전체 열만 보존하고 미확인 새 가격은 결측으로 유지합니다.

## 일일 입력 빈티지 연결

2026-10-21부터 일일 갱신은 마지막 정상 결과의 `inputCache`에 연결된 검증된 입력을 사용합니다. Yahoo의 과거 조정종가 재계산 잡음이 근접 신호 순위를 바꾸지 않도록 과거 조정가격 관측과 결측 상태를 유지합니다. 새 구간은 같은 새 다운로드 안의 경계 가격과 신규 가격의 비율로 기존 가격 단위에 연결합니다. 이전 NAV·보유비중·선택 결과를 복사하지 않고 전체 계산과 기존 10bp 역사 검증을 다시 실행합니다.

이 연결 전에는 전체 과거 원종가·거래량·배당·분할 기록, 달력, 가격 결측 상태가 일치해야 합니다. binary64 CSV 왕복 오차만 허용하며 공급자의 실제 역사 수정, 새 과거 관측, 가격 연결 경계 누락은 검토를 위해 중단합니다. 이 정책은 공급자의 수정 이력을 자동 승인하지 않습니다. 분할에 따른 과거 원자료 기준 변경도 자동으로 무시하지 않습니다.

새 원수집본은 수정하지 않습니다. 계산용 입력은 `raw/price-vintage`의 별도 해시 스냅샷이고, 결과의 `inputCache.priceVintageSnapshotId`가 다음 실행에 사용할 스냅샷을 고정합니다. `priceVintage` 기록은 수집본·이전 입력의 ID, 기준일, 종목별 경계가격과 변환 비율을 남깁니다. 기존 `raw`·`market` 캐시 경로를 유지하므로 변경 전 캐시도 복원할 수 있습니다. 이후 입력도 동일한 경로로 검증되며 캐시 유실 시 새 다운로드로 과거를 대체하지 않습니다.
