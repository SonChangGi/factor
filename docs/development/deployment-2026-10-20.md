`site/`는 검증한 통합 화면과 결과의 불변 배포 입력이다. `site/publication.json`은 모든 파일 hash, 결과·입력·계산 소스와 검증 범위를 연결한다. 배포 검사는 계산 당시 Git blob 17개까지 대조하며 변경되거나 추가된 미검토 파일을 거절한다.

Pages는 `scripts/build_integrated_publication.py`가 만든 `public/`를 올린다. 통합 화면은 `data/integrated-result.json`만 읽는다. 기존 Control과 기존 예약 수집의 소비자를 위해 `docs/data/`의 legacy JSON은 별도 역할로 원래 경로에 바이트 그대로 복사한다. `legacy-publication.json`은 그 파일들과 배포 소스를 기록한다. 통합 결과와 경로가 충돌하면 실패한다. 기존 Control 입력을 통합 입력으로 재해석하지 않는다.

배포 전후 출처 SHA를 검증하며 공개된 모든 파일을 바이트 단위로 재확인한다. watchdog도 동일 조립 경로를 사용한다. 기존 cron 문자열, 수집 입력과 수집 일정은 바꾸지 않는다. 기존 예약 수집이 통합 계산을 갱신하는 것은 아니며 해당 실행 요약에도 구분한다. 통합 계산 예약 전환과 Control 서비스 운영 환경 변경은 이번 배포에 포함하지 않는다.
